# Мини-CRM «Объекты и задачи» для строительной компании

Проект разработан в точном соответствии с техническим заданием: React + TypeScript + Supabase (PostgreSQL с RLS и триггерами) + Tailwind CSS.

---

## 🏗 Архитектура и стек технологий

- **Frontend**: React 19, TypeScript, Tailwind CSS v4, Lucide React, React Router v7.
- **Backend / Database**: Supabase (PostgreSQL 15+).
- **Безопасность данных**:
  - Строгий **Row Level Security (RLS)** на всех таблицах базы данных.
  - **Бизнес-логика и переходы статусов валидируются на стороне базы данных** через PostgreSQL триггеры (`trg_task_status_update`, `trg_task_insert`) и RPC-функцию `change_task_status`.
  - **Защита истории задач**: прямой `INSERT`, `UPDATE`, `DELETE` через Supabase API запрещены; история пишется исключительно серверными триггерами.
  - **Изоляция данных**: Исполнитель не может прочитать или изменить чужие задачи и видит только те стройки, где у него есть назначенные задачи.
  - **Секретные ключи**: ключ `service_role` не используется во фронтенде и добавлен в `.gitignore`.

## 👥 Роли и матрица прав доступа

| Действие | Постановщик (`manager`) | Исполнитель (`assignee`) |
|---|---|---|
| Просмотр объектов | Видит **все** объекты | Видит **только** объекты со своими задачами |
| Создание / редактирование / удаление объектов | ✅ Разрешено | ❌ Запрещено (RLS блокирует) |
| Просмотр задач | Видит **все** задачи | Видит **только** назначенные на него (`assignee_id = auth.uid()`) |
| Создание / редактирование / удаление задач | ✅ Разрешено | ❌ Запрещено (RLS блокирует) |
| Смена статусов | Принимает или возвращает на доработку | Берет в работу, отправляет на проверку |
| Просмотр истории изменений задачи | Видит для всех задач | Видит только для своих задач |
| Изменение / подделка истории | ❌ Запрещено всем через API | ❌ Запрещено всем через API |

## 🔄 Жизненный цикл задачи (Матрица переходов)

Переходы жестко контролируются базой данных (любой несанкционированный запрос через API будет отклонен триггером PostgreSQL):

| Из статуса | В статус | Кто может перевести | Условие |
|---|---|---|---|
| `—` | `Новая` | Постановщик | При создании задачи (начальный статус) |
| `Новая` | `В работе` | Назначенный исполнитель | — |
| `В работе` | `На проверке` | Назначенный исполнитель | — |
| `На проверке` | `Принята` | Постановщик | — |
| `На проверке` | `На доработке` | Постановщик | **Комментарий обязателен!** |
| `На доработке` | `В работе` | Назначенный исполнитель | — |

*Все остальные переходы строго запрещены и пресекаются триггером базы данных.*

## ☁️ Развёртывание в облачный Supabase

Подробная пошаговая инструкция с SQL-скриптами находится в директории [`supabase/README.md`](supabase/README.md):
1. Скопируйте и выполните [`supabase/schema.sql`](supabase/schema.sql) в SQL Editor панели Supabase.
2. Скопируйте и выполните [`supabase/seed.sql`](supabase/seed.sql) для создания тестовых пользователей и данных.
3. Отключите открытую регистрацию: **Authentication** -> **Providers** -> **Email** -> снимите флаг **Enable Signup**.
4. Скопируйте `URL` и `anon key` проекта в файл `.env`:
   ```env
   VITE_SUPABASE_URL=https://ваш-проект.supabase.co
   VITE_SUPABASE_ANON_KEY=ваш-anon-ключ
   ```
